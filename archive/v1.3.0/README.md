# YouTube Bilingual Subtitles

让官方 iPad YouTube App 显示 **DeepSeek 简体中文在上、英文在下**的双语字幕。使用 Quantumult X 重写英文字幕响应，无需更换播放器。当前正式版本：`v1.3.0`。

**使用边界：一小时以上等较长视频仍可能首次加载失败或中文不全。** 这不是固定的 60 分钟限制，实际取决于字幕量、网络、API 响应和 App 等待行为。本项目不保证冷启动首次 100% 完成，也无法把 QX 后续缓存进度直接追加到 App 已加载的字幕。

## 安装与升级

唯一正式订阅：

```text
https://raw.githubusercontent.com/qutary/youtube-bilingual-subtitles/main/YouTube.Bilingual.snippet
```

需要 iPad、官方 YouTube App、Quantumult X 和有效的 DeepSeek API Key。QX 需启用重写，正确配置相关字幕域名的 MitM，并信任证书。

- **已用正式订阅**：更新该资源及脚本即可，无需重设 Key 或清理缓存。
- **此前使用测试订阅**：切换到上述正式地址一次，并在 iPad 停用或移除其他字幕重写资源；同一时间只启用一份。本仓库更新不能直接修改 iPad 上的资源开关。
- **首次设置 Key**：把 [`set-deepseek-local.js`](./set-deepseek-local.js) 保存为 QX 本地私有脚本，填入自己的 Key 后运行一次；日志出现 `DeepSeek API key stored in Quantumult X local prefs.` 即保存成功。已设置 `QXYTB_DEEPSEEK_KEY` 的用户跳过此步。

在视频 CC 菜单选择 **English** 或 **English (auto-generated)**。选择的是英文源轨，不是 YouTube“自动翻译→中文”。已有 Key、有效语义缓存（SEM）及原条目缓存（FT）继续按对应轨道复用，不混用不匹配的缓存。

## 字幕与覆盖

先把跨英文字幕条目的句子接回句窗，再由 DeepSeek 翻译和划分中文意群。长句使用原文短语对齐，本地检查连续覆盖；匹配失败时按长度改用整窗中文或经过校验的词索引分组重试，不按固定词数硬切原句。无法可靠规划时保留原条目翻译回退。

**已通过校验的中文正常交付，只有缺失单元保留英文。** 不会因少数单元未完成而隐藏全部中文，日志如实显示已完成与缺失数量。本版也修复了更换等待预算后旧定时器可能提前结束响应的问题。

中英保留同段落内部换行及 110/140 样式字号，由原生播放器排版。仍为逐行黑底，不能保证中英文背景等宽等高。有源词时间时使用源时间；没有时在原字幕时段内估计，可能存在局部同步误差。

## 等待与生效范围

通常采用 **8 秒脚本目标、预留 400ms**；总词数超过 5000、句窗/条目超过 360，或超过 16 个长句窗时，采用 **15 秒、预留 600ms**。长句窗指超过 36 个英文词；以上是字幕量条件，不是视频时长阈值。预算不含 YouTube 源字幕返回前的等待，也不代表 App 一定接受该等待时长。

请求上限按初始批次数三倍设置，范围 36～512；长轨最多 12 路并发，初始批次超过 48 时最多 16 路。到期保留已完成结果。响应结束后不能继续更新 App 内那份字幕，拖动进度也未必触发新请求。

仅处理能识别为原生 iOS YouTube App 的请求。Safari、Chrome 及未知客户端原样放行，不读译文缓存、不调用 DeepSeek；识别依据请求特征，不是系统进程隔离。

## 隐私与验证

Key 存于 QX 本地偏好，不应写入公开仓库；翻译请求携带字幕及必要上下文发送至 DeepSeek，费用由用户的 API 账户承担。仅使用 DeepSeek，没有其他翻译服务或常驻后台任务。

40 项离线回归检查通过，覆盖定时器回退、部分中文交付、重试、缓存、对齐和旁路等路径。已有用户 iPad 排版与部分双语运行反馈，但不能据此宣称一小时以上视频的问题已解决。离线测试使用模拟 API，不等于实际翻译速度或中文质量测试。

仓库根目录仅保留 README、订阅、字幕脚本及本地 Key 模板四个文件。项目为非官方第三方工具，与 YouTube、Google、DeepSeek、Quantumult X 无隶属关系。
